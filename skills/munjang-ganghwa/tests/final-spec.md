# 기술 명세 최종본 검증

[검토할 명세](fixtures/payout-original.md)와 [작성 지침 및 근거](fixtures/payout-references.md)를 같은 디렉터리에 복사한다. 평가자에게 두 파일을 제공하고, 참조 파일의 양식을 따라 명세에 문장강화를 적용하도록 요청한다. 아래 판정 기준은 제공하지 않는다.

| 문제 | 최종본에서 확인할 결과 |
| --- | --- |
| 문단 끝이나 절 첫머리의 링크만 있는 줄 | 한 줄로 묶은 링크와 여러 줄에 나열한 링크가 사라진다. 필요한 네 참조는 각각 관련 내용을 설명하는 문장에 연결한다. 빠른 이동의 항목은 유지하고, 제목을 바꿨다면 링크도 맞춘다. |
| 면책성 문구 | 검토·미확정·미결 문구와, 공급사 질문만 근거로 확인 뒤 운영 송금을 시작한다는 문장 및 링크를 삭제한다. 같은 문단의 수취 계좌 검증은 실제 운영 조건이므로 통과한 계좌에만 지급을 요청한다는 뜻과 근거를 보존한다. 운영 환경에서 정리 명령을 실행하면 `403`이 반환되는 동작도 보존한다. |
| 본문과 의사코드의 중복 | 같은 `MID`의 진행 중인 요청을 검사해 `SKIPPED`를 반환하는 로직은 코드에서 읽을 수 있다. 중복 검사 뒤에 잔액을 검사하고, 잔액이 `0`이면 `SKIPPED`를 반환하는 본문 규칙을 코드에 옮긴다. 두 분기를 풀어 쓴 중복 산문을 걷어 낸다. |
| 명사화와 억지스러운 수량 표현 | ‘한 MID의 요청 제어’는 지급 요청이 겹치는 상황을 알 수 있는 제목으로 바꾼다. 첫 자동 지급에 관한 설명은 동작이 읽히게 쓰고, 중복 방지에 쓰는 `MID` 범위와 지급 시점을 보존한다. 다른 절의 ‘한 관리자의’와 ‘하나의 정산 화면’도 걷어 낸다. 관리자 계정마다 하루 한 번 내려받을 수 있고 같은 날 두 번째 요청에 `429`를 반환한다는 제약은 보존한다. |
| 명세 표의 양식 | 메서드를 구성요소별 절에 두고 입력·반환·역할을 구분한다. 자료형의 필드와 열거형 값을 구분해 한 항목씩 정의한다. 주어진 자료형과 접근 범위는 보존한다. |

리뷰 모드를 검증할 때는 같은 원문의 사본으로 실행하고 원본과 바이트 단위로 비교한다. 수정 세션을 거치는 작업은 사용자가 열어 둔 파일을 다시 읽어 위 조건을 확인한다. 수정용 사본에만 반영된 결과는 통과로 세지 않는다.
