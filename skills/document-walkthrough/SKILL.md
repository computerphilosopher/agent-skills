# 문서 길잡이

문서를 읽을 순서를 안내하고, 함께 읽으며 질문에 답하고 진도를 이어간다. 사용자가 지정한 대상·목적·범위와 설명 속도를 따른다.

## 호출

```text
$document-walkthrough 문서경로 어디부터 읽으면 좋을지 안내해줘.
$document-walkthrough 문서경로 호출 예부터 한 단계씩 설명해줘.
```

## 읽기 경로 안내

1. 대상 문서의 구조와 핵심 내용을 읽는다. 문서에서 직접 참조하는 정의도 이해에 필요한 범위에서 확인한다. 읽지 못한 자료는 그 사실을 밝히고, 내용을 확인한 것처럼 설명하지 않는다.
2. 사용자가 문서를 읽는 목적과 이미 아는 개념을 요청과 대화에서 파악한다. 읽을 순서나 설명 수준에 큰 영향을 주는 정보가 부족할 때만 질문한다.
3. 목차를 살피고 어떤 개념을 먼저 알아야 다음 내용을 이해할 수 있는지 확인한다. 이를 바탕으로 읽을 순서와 각 구간을 읽는 이유를 짧게 제안한다. 기술 명세라면 전체 흐름이나 호출 예를 먼저 보고, 거기에 나오는 개념·자료형·세부 조건을 찾아 읽도록 안내할 수 있다.

## 함께 읽기

- “하나씩” 요청하면 의미 있는 한 단계나 한 개념을 설명하고 다음 구간은 짧게 예고한다. “다음”이라고 하면 이어지는 구간을 설명한다.
- 동작을 설명할 때는 누가 어떤 조건에서 어떤 입력을 받아 무엇을 처리하는지 풀어 준다. 처리 목적과 결과를 밝히고, 그 결과가 다음 단계에 어떻게 쓰이는지 연결한다. 현재 단계의 진행을 바꾸는 실패 조건도 설명한다.
- 개념 중심 문서에서는 핵심 주장과 근거, 다른 개념과의 관계를 설명한다.
- 각 값이 어디에서 만들어져 누구에게 전달되고 어떤 처리에 쓰이는지 설명한다. 원문의 식별자를 유지하고 필요한 곳에 쉬운 풀이를 붙인다.
- “서버”처럼 여러 대상을 가리킬 수 있는 말은 설명하는 대상의 역할이나 구성요소 이름으로 구체화한다. 동작마다 수행 주체를 구별한다.
- 예시를 들 때는 같은 상황과 값을 다음 단계에서도 이어 쓴다. 설명을 위해 만든 예와 문서가 정한 값은 구별한다. 관계를 보여 주는 데 도움이 되면 짧은 표나 호출 흐름을 사용한다.
- 설명의 근거가 있는 절이나 행으로 링크한다. 링크 주변에 그곳에서 확인할 내용을 적는다.

## 질문에 답하기

- 구절이나 용어의 뜻을 물으면 필요한 문맥을 확인해 바로 설명한다. 질문마다 전체 읽기 계획을 다시 제안하지 않는다.
- 중간 질문에는 먼저 답하고 현재 읽는 구간과의 관계를 설명한다. 질문에 답했다고 다음 구간까지 설명한 것으로 처리하지 않는다. 사용자가 진행을 요청하지 않았다면 질문에 대한 답에서 마친다.
- “무슨 말이지?”라고 하면 낯선 용어의 뜻과 생략한 관계를 구체적인 예로 풀어 설명한다. 같은 설명을 표현만 바꿔 반복하지 않는다.

## 진도 이어가기

이미 읽고 있는 문서라면 현재 대화의 질문과 진도를 이어받는다.

- 대화에서 마지막으로 설명한 위치, 답한 질문과 남은 질문, 다음에 읽을 구간을 구분한다. 설명을 마쳤다는 이유로 사용자가 이해하거나 동의했다고 판단하지 않는다.
- “어디까지 봤지?”라고 하면 현재 진도와 앞서 설명한 핵심 내용을 짧게 안내한다. 대화 기록만으로 진도를 확정할 수 없으면 확인된 부분과 불확실한 부분을 구별한다.
- 읽기를 재개할 때는 관련 원문을 확인한다. 내용이나 순서가 개정됐다면 이전 설명과 달라진 점을 밝히고 현재 문서에서 이어 읽을 위치를 정한다.

## 근거와 작업 범위

- 문서에 명시된 내용과 추론을 구분한다. 설계 이유나 정책 근거가 없으면 확인되지 않았다고 밝힌다. 가능한 이유를 제시할 때는 추론임을 명시한다.
- 쉽게 설명하더라도 주체·조건·예외·수치·처리 순서를 보존한다. 문서의 모순이나 누락은 숨기지 않고 확인할 질문으로 남긴다.
- 읽기 안내나 의미 설명 요청만으로 원문을 수정하지 않는다. 사용자가 수정을 요청하면 지정한 범위에서 처리하고, 변경으로 앞선 설명이나 다음에 읽을 구간이 달라지는지 확인한다.
