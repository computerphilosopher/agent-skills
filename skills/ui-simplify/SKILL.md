# UI 간소화

리뷰에서 확인한 문제는 프론트엔드 코드에서 바로 수정한다. 사용자가 “리뷰만 해줘”처럼 수정 없이 검토해 달라고 명시하면 발견 사항과 이유만 전달한다.

## 텍스트

당연한 설명, 같은 내용의 반복, 화면을 보면 알 수 있는 조작 안내를 찾는다. 문구를 빼도 사용자가 이해하고 진행할 수 있으면 삭제한다. 필요한 안내는 짧고 정확하게 쓴다.

모든 UI 문구에서 가운뎃점(·)을 쓰지 않는다. 기존 문구에 있으면 “이용·결제 내역”을 “이용 내역과 결제 내역”으로 고치는 식으로 뜻에 맞게 풀어 쓴다.

## 버튼

역할이 겹치거나 현재 상황에서 쓸모없는 버튼을 찾는다.

## 환경에 따른 UI 분기

기본적으로 개발·테스트·운영 환경에서 같은 UI를 제공한다. “개발용 테스트 화면입니다”처럼 환경을 알리기 위한 문구나 배지를 추가하지 않는다.

프론트엔드 코드에서 환경에 따라 달라지는 화면 요소와 그 표시 조건을 찾는다. 명시적인 제품 요구사항이 없는 경우 해당 요소와 표시 조건을 함께 제거한다. 환경 판별 변수나 헬퍼는 다른 사용처를 확인하고, 해당 UI에서만 쓰면 함께 정리한다.

## 리뷰 결과

어디를 어떻게 수정했는지 이유와 함께 짧게 보고한다. 삭제만으로 충분하면 대체 문구나 새 버튼을 만들지 않는다. 동작을 확인할 수 없는 요소는 그대로 두고 확인이 필요한 이유를 알린다.
