# Document Thanos

문서에서 독자에게 필요한 정보를 보태지 않는 내용을 찾아 삭제하거나 통합한다. 삭제량이나 비율을 목표로 삼지 않는다.

이 스킬로 문서를 정리해 달라는 요청에는 실제로 수정한다. 검토나 제안만 요청받으면 파일을 바꾸지 않고 삭제 후보와 근거를 보고한다.

## 삭제 판단

각 설명이 대상 독자의 어떤 구체적인 질문에 답하는지 확인한다. 그 설명을 뺐을 때 독자가 놓치는 의미·조건·관계·판단 근거·절차가 무엇인지 주변 문맥과 함께 살핀다. 필요한 정보가 그대로 남는다면 삭제하거나 중복을 통합한다.

"이해를 돕는다", "틀린 말은 아니다", "친절한 설명이다", "혹시 필요할 수 있다"만으로 유지하지 않는다. 유지할 이유는 실제 독자의 이용 상황이나 명시적 작성 규칙에서 확인한다. 필요성을 판단할 정보가 부족하면 확인할 질문을 남기고, 유지 이유를 임의로 만들거나 불필요하다고 단정하지 않는다.

표현이 달라도 같은 사실을 전달하면 중복 후보로 본다. 필요한 요약·예시·비교값과 독립적으로 읽는 구간의 설명은 각 위치에서 맡는 역할을 확인해 유지한다. 표나 절에 중복과 고유 정보가 섞여 있으면 필요한 내용을 남길 위치를 정한 뒤 중복을 제거한다.

## 삭제 후보

- 제목·이름·앞선 정의를 풀어 쓸 뿐 새 정보를 주지 않는 문장, 막연한 편의성이나 유용성을 설명하는 부연.
- 본문·표·의사코드에서 같은 조건·필드 조합·처리 순서·오류 규칙을 상세하게 반복한 부분. 상세 정의 한곳과 필요한 요약·링크로 정리한다.
- 선택하지 않은 구현, 저장하지 않을 값, 표시하지 않을 상태를 열거하는 대안 해명. 실제 제약을 전달하는 부정문은 적용 조건과 효과를 보존한다.
- 현재 설계를 설명하는 곳에 남은 이전 선택이나 변경 경위. 현재 동작을 직접 설명하고, 보존이 필요한 경위는 이력으로 옮길 항목으로 남긴다.
- 문서가 맡지 않은 질문에 답하는 내용. 대상 문서 안에 적합한 위치가 있으면 옮긴다. 다른 문서에서 필요한 고유 정보는 이동할 위치를 제안하고, 옮기기 전에 원문을 삭제하지 않는다.

## 작업 절차

1. 대상 문서 전체와 적용되는 작성 규칙을 읽고 목적·독자·검토 범위를 확인한다. 연결된 정의와 주변 문서는 삭제 판단이나 참조 확인에 필요한 범위에서 읽는다.
2. 모든 문단·목록·표·예시와 절에 삭제 판단을 적용한다. 같은 원인의 후보는 함께 확인하고, 중복이라면 남길 정의의 위치와 내용을 실제로 확인한다.
3. 요청 범위 안에서 삭제·통합하고 문맥을 잇는 데 필요한 제목·연결 문구·참조만 다듬는다. 문서에 정해진 의미·정책·설계, 필요한 배경·정의·조건·예외·주의사항, 원문 인용과 역사적 기록은 보존한다.
4. 수정한 문맥과 관련 표·예시·링크를 다시 읽는다. 삭제 후에도 독자가 같은 조건에서 같은 내용과 행동·결과를 이해할 수 있는지 확인한다. 링크가 가리키는 정의가 실제로 남아 있는지, 참조만 서로 순환하지 않는지 확인하고 저장소에서 요구하는 관련 검사를 실행한다.

## 결과 보고

변경한 위치별로 **삭제·통합한 내용 → 필요한 정보가 보존되는 근거**를 짧게 보고한다. 중복을 없앴다면 남긴 정의의 위치를 제시한다.

검토 범위와 판단하지 못한 부분, 이동 제안이 필요한 고유 정보를 밝힌다. 모든 설명의 유지 이유를 나열하지 않는다. 정리할 내용이 없으면 없다고 보고하고 끝낸다.
