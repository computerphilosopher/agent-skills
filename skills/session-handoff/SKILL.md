# Session Handoff

다음 대화가 현재 작업을 바로 이어갈 수 있도록 필요한 맥락과 작업 자료를 인계한다.

## 실행 방식

- **프롬프트 작성:** 인수인계 프롬프트·요약만 요청했거나 이 스킬만 호출했다면 사용자 언어로 짧은 텍스트 코드 블록 하나를 작성한다. 대화 생성이나 아카이브는 실행하지 않는다.
- **실제 이관:** 새 대화를 만들어 인수인계하라고 요청하면 앱 도구로 생성부터 인수 확인까지 진행한다. 기존 대화의 아카이브도 요청했다면 인수가 확인된 뒤 실행한다. 이미 받은 승인은 다시 묻지 않으며, 사용자가 직접 확인하겠다고 정한 조건은 기다린다.
- 스킬 수정 요청은 실제 대화 이관이나 아카이브 요청으로 해석하지 않는다.

## 포함할 정보

- 이어갈 목표와 현재 승인 범위. 구현 미승인처럼 다음 행동을 제한하는 결정은 유지한다.
- 작업 위치와 시작할 기준 문서. 절대 경로를 사용하고, 기준 문서에서 따라갈 수 있는 연결 문서 목록은 생략한다.
- 파일에 없는 최신 결정, 진행 중인 작업, 막힌 이유, 바로 다음 행동 중 실제로 필요한 내용만 남긴다. 제안과 확정을 구분한다.
- Git 작업이면 경로 실존 여부와 현재 checkout·브랜치·전체 HEAD·미커밋 변경을 확인한다. 미커밋 변경이 어느 작업에 속하는지 밝히고, 현재 작업 폴더가 기본 체크아웃인지 별도 워크트리인지 적는다. 푸시 여부는 확인한 경우에만 적는다. 확인할 수 없는 상태는 이어가기 전에 확인하도록 남긴다.
- 공통 규칙은 `AGENTS.md` 등 원문을 따르라는 한 줄로 갈음한다.

## 줄이는 기준

각 문장에 “이 내용이 없으면 다음 세션이 작업을 잘못 이어가는가?”를 적용한다. 완료 내역, 대화 경과, 시행착오, 검사 결과 목록, 반복 설명, 빈 항목은 빼고 저장된 내용은 기준 문서로 대신한다. 미반영 결정과 복구에 필요한 정보는 짧게 유지한다. 상세 형식을 요청받으면 그 범위를 따른다.

## 이관 자료 준비

기존 대화를 아카이브할 예정이고 앱 관리 워크트리에서 작업했다면 원본 저장소 경로, 기준 브랜치, 전체 커밋 SHA와 변경 상태를 기록한다. 인수 조건에는 새 대화에 연결된 별도 워크트리, 기준 HEAD 일치, 기준 파일과 전달 자료의 존재를 포함한다. 기존 워크트리와 기본 checkout은 유지하며, 기존 브랜치가 사용 중이면 detached HEAD 또는 새 작업 브랜치를 사용한다.

미커밋 변경과 필요한 미추적·ignored 파일은 커밋 SHA만으로 전달되지 않는다. 필요한 자료를 식별하고 승인 범위 안에서 별도로 보존·전달한 뒤 위치와 복원 방법을 기록한다. 새 대화가 해당 자료까지 확인하기 전에는 인수 완료로 보지 않는다. 스냅샷 ID는 실제 조회한 값과 사용 가능한 복원 방법이 확인된 경우에만 전달한다. 프롬프트 작성이나 대화 생성 자체는 파일 보존을 대신하지 않는다.

## 실제 이관 절차

Git·워크트리 절차는 저장소 작업에만 적용한다. 저장소 없는 작업은 `projectless` 대화로 생성하고 필요한 자료의 실제 경로와 존재 여부를 확인한다.

1. **출발 위치를 확인한다.** 관련 앱 도구를 찾아 현재 명세를 읽는다. Git 상태와 `list_artifacts`로 기존 작업 위치를 확인한다. 현재 대화의 아카이브는 도구의 호출 대화 지정 방식을 사용하며 ID를 추측하지 않는다. 저장소 작업은 `list_projects`에서 대상 프로젝트를 확인한다.
2. **새 대화를 생성한다.** `create_thread`에 위 기준으로 작성한 인수인계 내용을 전달한다. 사용자가 별도 워크트리와 특정 Git 상태에서 시작하도록 요청했다면 `worktree` 환경과 해당 SHA ref를 지정한다. `create_thread`의 이 매개변수 조건에 해당하지 않으면 로컬 대화를 만들고, 새 대화가 연결 상태를 확인한 뒤 `create_worktree`로 인수 대상 SHA의 별도 워크트리를 준비하도록 지시한다. 인수 위치가 마련되기 전에는 기본 체크아웃을 수정하지 않는다. 기준 SHA를 기본 브랜치로 임의 대체하지 않는다. 앱이 만든 워크트리가 있으면 새 대화가 그것을 사용하고 중복 생성하지 않도록 지시한다. 모델은 사용자가 지정한 경우에만 설정한다.
3. **생성 결과를 추적한다.** `clientThreadId`만 반환되면 생성 진행 중이다. 재호출해 대화를 중복 생성하지 말고 `list_threads`에서 프로젝트·작업 경로·제목으로 실제 `threadId`를 확인한다. 임시 ID를 실제 대화 ID가 필요한 도구에 넘기지 않는다.
4. **인수 응답을 기다린다.** 실제 ID와 host로 `wait_threads`를 호출한다. 처음에는 `timeoutMs: 0`으로 상태를 읽고, 이후 반환된 cursor를 사용해 한 번에 60초 이내로 기다린다. 새 대화에는 작업 경로, 브랜치 또는 detached 상태, 전체 HEAD, 변경 상태, 기준 문서와 전달 자료의 확인 결과를 보고하도록 한다. 구현 등 후속 작업은 기존 승인 범위를 따른다.
5. **인수 조건을 검증한다.** 새 대화가 완료됐다는 상태만으로 성공 처리하지 않는다. 보고된 HEAD와 파일·자료가 인수 조건을 충족하는지 확인한다. 불일치·누락·추가 입력 요청이 있으면 기존 대화를 유지한다. 이관 요청에 필요한 보완은 새 대화에 전달하고 다시 확인한다. 시간 초과나 도구 사용 불가는 인수 완료가 아니며, 확인할 수 없는 상태와 남은 작업을 보고한다.
6. **승인된 아카이브를 실행한다.** 아카이브까지 요청받았다면 실행 직전에 기존 작업 위치에 인계 이후의 변경이 생겼는지 확인한다. 추가 변경이 있으면 새 기준 SHA 또는 전달할 패치·자료 상태를 명시해 인계 기준을 갱신하고 재확인한다. 인수 조건과 사용자가 정한 확인 조건을 충족한 뒤 `set_thread_archived(archived: true)`에서 `threadId`를 생략해 호출 중인 기존 대화를 아카이브하고 성공 응답을 확인한다. 다른 대화를 대상으로 요청받은 경우에만 확인한 ID와 host를 지정한다. 새 대화를 대상으로 지정하지 않는다. 아카이브가 실패하면 인수 완료와 아카이브 미완료를 구분해 보고한다.
7. **결과를 전달한다.** 새 대화의 실제 제목, 새 작업 위치의 기준 문서 링크, 인수 결과와 기존 대화의 아카이브 여부를 짧게 알린다. 성공한 생성 호출에는 `::created-thread{threadId="..."}`를 표시한다. 아직 실제 ID를 확보하지 못한 경우에만 반환된 `clientThreadId`로 표시하고 생성·인수 대기 상태를 명시한다.

아카이브는 대화 상태 변경이다. 별도 요청 없이 `archive_worktree`나 Git 삭제 명령으로 기존 워크트리·브랜치를 정리하지 않는다. 도구가 없으면 수행하지 못한 단계를 밝히고 인수인계 프롬프트를 제공하며, 생성·인수·아카이브가 끝났다고 말하지 않는다.

인수인계 프롬프트를 별도 파일로 저장하는 것은 요청받은 경우에만 한다. 인수인계를 이유로 커밋·푸시·기존 워크트리 이동이나 삭제를 함께 실행하지 않는다. 확인할 수 없는 컨텍스트 잔량을 추정하거나 자동 실행을 약속하지 않는다.
