# Session Handoff

현재 작업을 새 대화로 이관하고, 저장소 작업이면 별도 워크트리를 준비하며, 인수 확인 후 기존 대화를 아카이브한다.

## 실행 방식

- **기본 실행:** 이 스킬만 호출해도 새 대화 생성, 저장소 작업의 별도 워크트리 준비, 자료 인계, 인수 확인, 기존 대화 아카이브까지 실행한다. 스킬 실행 요청은 이 전체 절차에 대한 명시적 요청으로 취급하며, 새 대화·워크트리·아카이브를 따로 요청하도록 요구하지 않는다. 이미 받은 승인은 다시 묻지 않으며, 사용자가 직접 확인하겠다고 정한 조건은 기다린다.
- **프롬프트만 작성:** 사용자가 인수인계 프롬프트만 달라고 명시한 경우에만 사용자 언어로 짧은 텍스트 코드 블록 하나를 작성한다. 대화 생성, 워크트리 준비, 아카이브는 실행하지 않는다.
- 스킬 자체의 설명·검토·수정 요청은 실행 요청으로 해석하지 않는다.

## 포함할 정보

- 이어갈 목표와 현재 승인 범위. 구현 미승인처럼 다음 행동을 제한하는 결정은 유지한다.
- 작업 위치와 시작할 기준 문서. 절대 경로를 사용하고, 기준 문서에서 따라갈 수 있는 연결 문서 목록은 생략한다.
- 파일에 없는 최신 결정, 진행 중인 작업, 막힌 이유, 바로 다음 행동 중 실제로 필요한 내용만 남긴다. 제안과 확정을 구분한다.
- Git 작업이면 경로 실존 여부와 현재 checkout·브랜치·전체 HEAD·미커밋 변경을 확인한다. 미커밋 변경이 어느 작업에 속하는지 밝히고, 현재 작업 폴더가 기본 체크아웃인지 별도 워크트리인지 적는다. 푸시 여부는 확인한 경우에만 적는다. 확인할 수 없는 상태는 이어가기 전에 확인하도록 남긴다.
- 공통 규칙은 `AGENTS.md` 등 원문을 따르라는 한 줄로 갈음한다.

## 줄이는 기준

각 문장에 “이 내용이 없으면 다음 세션이 작업을 잘못 이어가는가?”를 적용한다. 완료 내역, 대화 경과, 시행착오, 검사 결과 목록, 반복 설명, 빈 항목은 빼고 저장된 내용은 기준 문서로 대신한다. 미반영 결정과 복구에 필요한 정보는 짧게 유지한다. 상세 형식을 요청받으면 그 범위를 따른다.

## 이관 자료 준비

저장소 작업이면 원본 저장소 경로, 기준 브랜치, 전체 커밋 SHA와 변경 상태를 기록한다. 인수 조건에는 새 대화에 연결된 별도 워크트리, 기준 HEAD 일치, 기준 파일과 전달 자료의 존재를 포함한다. 기존 워크트리와 기본 checkout은 유지하며, 기존 브랜치가 사용 중이면 detached HEAD 또는 새 작업 브랜치를 사용한다.

미커밋 변경과 필요한 미추적·ignored 파일은 커밋 SHA만으로 전달되지 않는다. 필요한 자료를 식별하고 승인 범위 안에서 별도로 보존·전달한 뒤 위치와 복원 방법을 기록한다. 새 대화가 해당 자료까지 확인하기 전에는 인수 완료로 보지 않는다. 스냅샷 ID는 실제 조회한 값과 사용 가능한 복원 방법이 확인된 경우에만 전달한다. 프롬프트 작성이나 대화 생성 자체는 파일 보존을 대신하지 않는다.

## 실제 이관 절차

Git·워크트리 절차는 저장소 작업에만 적용한다. 저장소 없는 작업은 `projectless` 대화로 생성하고 필요한 자료의 실제 경로와 존재 여부를 확인한다.

1. **출발 위치를 확인한다.** 관련 앱 도구를 찾아 현재 명세를 읽는다. Git 상태와 `list_artifacts`로 기존 작업 위치를 확인한다. 이관 재시도라면 기존 생성 응답·딥링크·임시 확인 파일로 대상 대화 확인부터 재개하고, 이미 요청한 대화를 다시 생성하지 않는다. 처음 생성할 때는 해당 host의 대화 ID 목록을 확보한다. 같은 host에서 이관할 때는 양쪽에서 접근할 수 있는 고유한 임시 디렉터리를 만들고 `recipient.json` 경로를 정한다. 현재 대화의 아카이브는 도구의 호출 대화 지정 방식을 사용하며 ID를 추측하지 않는다. 저장소 작업은 `list_projects`에서 대상 프로젝트를 확인한다.
2. **새 대화를 먼저 생성한다.** `create_thread`에 위 기준으로 작성한 인수인계 내용을 전달한다. 저장소 작업은 `target.environment`를 `{type: "local"}`로 지정해 대화부터 생성한다. 워크트리 준비는 새 대화가 수행하도록 인수 프롬프트에 포함한다. 대화와 워크트리를 한 요청에 묶는 `worktree` 환경은 실제 대화 ID를 찾지 못하는 경로를 피하기 위해 기본값으로 사용하지 않는다. 같은 host의 새 대화에는 첫 행동으로 자기 실행 환경의 `CODEX_THREAD_ID`를 읽어 지정된 `recipient.json`에 `threadId`로 기록하도록 지시한다. 값이 없으면 ID를 추측하지 말고 그 사실을 보고하도록 한다. 파일에는 대화 식별자만 저장하고, 임시 파일 작성 후 이름 변경으로 완성된 JSON을 게시한다. 모델은 사용자가 지정한 경우에만 설정한다.
3. **실제 대화 ID로 직접 확인한다.** 생성 응답의 `threadId`, 사용자가 전달한 `codex://threads/<threadId>` 딥링크, 새 대화가 남긴 `recipient.json`은 목록 조회와 별개인 ID 확인 경로다. 확인된 ID와 host로 `read_thread`를 호출해 제목·초기 요청이 이번 이관과 일치하는지 확인하고 인수 추적으로 진행한다. `list_threads`에 다시 나타날 때까지 기다리지 않는다. `clientThreadId`만 있으면 생성 요청 접수만 확인된 상태이며, 실제 대화가 생성되지 않았다고 단정하지 않는다. 임시 확인 파일과 `list_threads`의 recent·해당 host의 codex history를 확인하고, 필요한 경우 `nextCursor`를 따라간다. 워크트리 준비 전의 경로는 기본 checkout일 수 있으므로 새 워크트리 경로만으로 대상을 찾지 않는다. 같은 결과가 반복되면 최대 2분 안에서 간격을 두고 재확인한 뒤 실제 ID 조회·인수 확인 미완료로 보고한다. 같은 생성 요청을 반복하거나 임시 ID를 실제 ID가 필요한 도구에 넘기지 않는다. 목록에 없다는 이유만으로 사용자에게 생성 항목 취소를 요구하지 않는다.
4. **새 대화의 워크트리 준비와 인수 응답을 기다린다.** 저장소 작업이면 새 대화는 자신의 `list_artifacts`로 연결 상태를 먼저 확인한다. 인수 기준에 맞는 별도 워크트리가 이미 연결돼 있으면 사용한다. 없으면 자신의 작업 폴더나 허용된 workspace에서 해당 저장소와 기준 SHA에 접근할 수 있는지 확인하고, 그 저장소 경로를 `sourceRoot`, 기준 SHA를 `ref`로 지정해 `create_worktree(allowAsync: true)`를 호출한다. 원본 자료 경로와 도구에 허용된 저장소 경로를 구분한다. `operationId`가 반환되면 `get_worktree_creation_status`로 완료와 연결 결과를 확인한다. 인수 위치가 마련되기 전에는 기본 체크아웃을 수정하지 않고, 기준 SHA를 기본 브랜치로 임의 대체하지 않으며, 워크트리를 중복 생성하지 않는다. 이 준비 지시를 최초 인수 프롬프트에 포함한다. 부모 대화는 실제 ID와 host로 `wait_threads`를 호출한다. 처음에는 `timeoutMs: 0`으로 상태를 읽고, 이후 반환된 cursor를 사용해 한 번에 60초 이내로 기다린다. 새 대화에는 작업 경로, 브랜치 또는 detached 상태, 전체 HEAD, 변경 상태, 기준 문서와 전달 자료의 확인 결과를 보고하도록 한다. 구현 등 후속 작업은 기존 승인 범위를 따른다.
5. **인수 조건을 검증한다.** 새 대화가 완료됐다는 상태만으로 성공 처리하지 않는다. 보고된 HEAD와 파일·자료가 인수 조건을 충족하는지 확인한다. 불일치·누락·추가 입력 요청이 있으면 기존 대화를 유지한다. 이관 요청에 필요한 보완은 새 대화에 전달하고 다시 확인한다. 시간 초과나 도구 사용 불가는 인수 완료가 아니며, 확인할 수 없는 상태와 남은 작업을 보고한다.
6. **기존 대화를 아카이브한다.** 실행 직전에 기존 작업 위치에 인계 이후의 변경이 생겼는지 확인한다. 추가 변경이 있으면 새 기준 SHA 또는 전달할 패치·자료 상태를 명시해 인계 기준을 갱신하고 재확인한다. 인수 조건과 사용자가 정한 확인 조건을 충족한 뒤 `set_thread_archived(archived: true)`에서 `threadId`를 생략해 호출 중인 기존 대화를 아카이브하고 성공 응답을 확인한다. 다른 대화를 대상으로 요청받은 경우에만 확인한 ID와 host를 지정한다. 새 대화를 대상으로 지정하지 않는다. 아카이브가 실패하면 인수 완료와 아카이브 미완료를 구분해 보고한다.
7. **결과를 전달한다.** 새 대화의 실제 제목, 새 작업 위치의 기준 문서 링크, 인수 결과와 기존 대화의 아카이브 여부를 짧게 알린다. 성공한 생성 호출에는 `::created-thread{threadId="..."}`를 표시한다. 아직 실제 ID를 확보하지 못한 경우에만 반환된 `clientThreadId`로 표시하고, 생성 요청 접수와 실제 대화 ID 조회·인수 확인 미완료를 구분해 명시한다. 임시 확인 파일을 썼다면 인수 확인 후 자신이 만든 파일만 정리한다.

아카이브는 대화 상태 변경이다. 별도 요청 없이 `archive_worktree`나 Git 삭제 명령으로 기존 워크트리·브랜치를 정리하지 않는다. 도구가 없으면 수행하지 못한 단계를 밝히고 인수인계 프롬프트를 제공하며, 생성·인수·아카이브가 끝났다고 말하지 않는다.

인수인계 프롬프트를 별도 파일로 저장하는 것은 요청받은 경우에만 한다. 인수인계를 이유로 커밋·푸시·기존 워크트리 이동이나 삭제를 함께 실행하지 않는다. 확인할 수 없는 컨텍스트 잔량을 추정하거나 자동 실행을 약속하지 않는다.
