# Session Handoff

컨텍스트가 부족하거나 새 대화로 옮길 때, 다음 세션이 바로 이어갈 수 있는 인수인계 프롬프트를 작성한다. 기본 출력은 사용자 언어로 쓴 짧은 텍스트 코드 블록 하나다.

## 포함할 정보

- 이어갈 목표와 현재 승인 범위. 구현 미승인처럼 다음 행동을 제한하는 결정은 유지한다.
- 작업 위치와 시작할 기준 문서. 절대 경로를 사용하고, 기준 문서에서 따라갈 수 있는 연결 문서 목록은 생략한다.
- 파일에 없는 최신 결정, 진행 중인 작업, 막힌 이유, 바로 다음 행동 중 실제로 필요한 내용만 남긴다. 제안과 확정을 구분한다.
- Git 작업이면 경로 실존 여부와 현재 checkout·브랜치·HEAD·미커밋 변경을 확인한다. 미커밋 변경이 어느 작업에 속하는지 밝히고, 현재 작업 폴더가 기본 체크아웃인지 별도 워크트리인지 적는다. 푸시 여부는 확인한 경우에만 적는다. 확인할 수 없는 상태는 이어가기 전에 확인하도록 남긴다.
- 공통 규칙은 `AGENTS.md` 등 원문을 따르라는 한 줄로 갈음한다.

## 줄이는 기준

각 문장에 “이 내용이 없으면 다음 세션이 작업을 잘못 이어가는가?”를 적용한다. 완료 내역, 대화 경과, 시행착오, 검사 결과 목록, 반복 설명, 빈 항목은 빼고 저장된 내용은 기준 문서로 대신한다. 미반영 결정과 복구에 필요한 정보는 짧게 유지한다. 상세 형식을 요청받으면 그 범위를 따른다.

## 아카이브 전 인수

기존 대화를 아카이브할 예정이고 앱 관리 워크트리에서 작업했다면, 인수인계에 다음 내용을 포함한다.

- 원본 저장소의 절대 경로, 기준 브랜치, 전체 커밋 SHA, 미커밋 변경 유무를 적는다.
- 새 대화에서 해당 커밋을 기준으로 새 대화에 연결된 별도 워크트리를 생성하도록 지시한다. 기존 워크트리와 기본 checkout은 유지하며, 기존 브랜치가 사용 중이면 detached HEAD 또는 새 작업 브랜치를 사용한다.
- 새 워크트리의 HEAD가 기준 커밋과 일치하고, 기준 파일과 전달할 변경이 모두 있는지 확인한 뒤 인수 완료를 알리도록 한다. 사용자는 인수 완료를 확인한 다음 기존 대화를 아카이브한다.

미커밋 변경과 필요한 미추적·ignored 파일은 커밋 SHA만으로 전달되지 않는다. 이런 자료가 있으면 별도 보존이 필요하다는 점과 확인된 보존 위치를 남긴다. 스냅샷 ID는 실제로 조회한 값과 새 대화에서 사용할 수 있는 복원 방법이 확인된 경우에만 전달한다. 인수인계 프롬프트를 작성해도 파일이 별도로 보존되지는 않는다.

파일 저장은 요청받은 경우에만 하며, 커밋·푸시·새 대화 생성·워크트리 이동이나 삭제를 함께 실행하지 않는다. 확인할 수 없는 컨텍스트 잔량을 추정하거나 자동 실행을 약속하지 않는다.
