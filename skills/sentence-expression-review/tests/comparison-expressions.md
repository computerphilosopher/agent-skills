# 비교 표현 검증

## 실행

평가자에게 [스킬](../SKILL.md)과 [검토 자료](fixtures/comparison-expressions-original.md)만 제공하고, `review` 모드로 세 사례를 검토하도록 요청한다. 3번은 제안된 수정안의 의미 보존 여부도 판단하도록 한다. 이 파일의 기대 결과와 이전 평가 결과는 제공하지 않는다.

## 판정 기준

특정 문구와 심각도 등급의 일치보다 다음 판단과 의미 보존 여부를 확인한다.

| 사례 | 기대 결과 |
| --- | --- |
| 1 | ‘입력 규칙’이 무엇을 가리키는지 불분명함을 지적한다. 수정안에는 관리자 웹과 첫 관리자를 등록하는 스크립트, 검사할 항목이 드러나고 두 경로에 적용하는 기준이 같다는 의미가 남아야 한다. 공통 검증기를 명시해도 된다. 제공되지 않은 아이디 형식은 만들지 않는다. |
| 2 | 바로 앞에서 두 조건을 밝혔으므로 ‘같은 규칙’을 유지한다. 해당 단어가 있다는 이유로 조건을 반복하거나 문장을 고치지 않는다. |
| 3 | 제안된 수정안은 원문의 뜻을 보존하지 못한다고 판단한다. 경로별로 검사할 항목을 나눈 문제를 지적하며, 대안을 제시한다면 두 경로 모두 비밀번호와 휴대폰 번호의 두 조건을 검사한다는 뜻을 보존한다. |

## 검증 한계

이 자료는 모호한 비교 표현의 구체화, 명확한 참조의 유지, 수정 시 공통점의 보존을 확인한다. 평가 한 번의 성공만으로 다른 문서에서도 표현 문제가 항상 교정된다고 판단하지 않는다.
